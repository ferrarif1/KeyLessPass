# ASTER paper blueprint

## Working title

**ASTER: Non-Reconstructing Exact-Domain Credential Derivation with
Authorization Confinement and Post-Compromise Root-Epoch Healing**

Alternative shorter title:

**ASTER: Authorization-Scoped Threshold Exact Rotation for Legacy Credentials**

## One-sentence thesis

A legacy-password manager does not need to choose between deterministic
reconstruction and endpoint-wide key exposure: exact policy-space passwords can
be generated by a scoped threshold service that releases only one authorized
generation at a time, while a fresh Root-Epoch migration protocol provides
actual recovery after root compromise.

## Draft abstract

Legacy enterprise systems often expose no authentication interface beyond a
policy-constrained text password. Deterministic password generators avoid
storing service-password values, but a client that reconstructs a master or
lineage key during normal use can turn a single endpoint compromise into
multi-credential or multi-generation exposure. Distributed PRFs avoid key
reconstruction, yet a broad evaluation interface can still amplify one
authorization into many legitimate credential outputs, and proactive resharing
of an unchanged root does not repair a root that has already been disclosed.

We present ASTER, an authorization-scoped threshold architecture for exact-domain
legacy credential derivation and post-compromise migration. A password policy is
compiled to a finite accepted language with exact Rank/Unrank functions.
Independent evaluator domains jointly realize a permutation over the exact rank
domain; each evaluation requires a short-lived capability bound to the complete
credential context, Root-Epoch, generation, operation, freshness state, and use
budget. The endpoint receives only the authorized password and never receives a
Root-Epoch or reusable lineage key during normal operation. When compromise is
suspected, ASTER generates an independent new Root-Epoch and migrates credentials
individually. Cross-epoch password-history exclusion is evaluated inside the
threshold service, and an evidence-bounded state machine retains both old and
candidate derivation paths when the remote password-change result is ambiguous.

We formalize exact-domain injectivity, capability confinement,
authorization-budget non-amplification, safe epoch retirement, and a scoped
post-compromise healing property. An executable reference model exercises
positive invariants and negative controls; the full artifact will instantiate
the evaluator with an actively secure MPC backend, reuse a public password-policy
corpus, inject remote-rotation faults, and model-check the migration protocol.
ASTER does not claim a new MPC, OPRF, secret-sharing, or format-preserving
encryption primitive; its contribution is the credential-specific composition
that simultaneously removes reusable derivation secrets from the endpoint and
provides failure-safe root replacement.

## Core novelty boundary

Do **not** claim the following as new:

- Shamir secret sharing;
- threshold PRF / threshold POPRF;
- proactive share refresh;
- generic constrained/scoped capability tokens;
- MPC evaluation of symmetric cryptography;
- FF1 / format-preserving encryption;
- finite-language Rank/Unrank;
- generic two-phase commit.

Claim ASTER at the **credential protocol** level:

1. **Non-reconstructing exact-domain credential sequence.**
   Strict no-repeat is preserved while the endpoint never receives the key that
   defines the sequence.

2. **Evaluation authority is generation-scoped.**
   The normal endpoint gets a one-request capability, not a reusable derivation
   secret.  The paper measures exposure as a function of authorization budget
   and compromise domains.

3. **Root-Epoch healing, not share refresh.**
   A compromised root is replaced by an independent root; credentials migrate
   with old/new ambiguity preserved until remote evidence is conclusive.

4. **Private cross-epoch history exclusion.**
   Candidate generations under the new root are checked against authenticated
   old history inside the threshold computation; rejected candidates are not
   persisted as password history.

## Minimum publishable artifact

A paper should not be submitted until all of the following exist:

- real 2-of-3 threshold/MPC evaluator implementation;
- ASTER exact-policy compiler with arbitrary-precision counting and Rank/Unrank;
- signed capability verifier on every evaluator;
- durable single-use/replay state;
- Root-Epoch DKG/replacement;
- per-record migration journal;
- at least two real adapter families (e.g. HTTP form + LDAP/OpenLDAP);
- crash/fault injection at every persistence/network boundary;
- public policy corpus evaluation;
- LAN and WAN benchmarks;
- model checking with negative controls;
- reproducible experiment scripts and raw results.

## Experimental claims to target

The target outcome is not “zero failures because the model is simple.”  The
paper should show quantitative separation:

- injected endpoint root exposure: compromise during derivation exposes a
  reusable derivation secret;
- exact-ticket threshold PRF: root remains hidden but independent PRF outputs do
  not provide the same exact no-repeat sequence contract;
- ASTER: endpoint-only compromise yields only ticket-authorized outputs;
- wildcard/projection ticket negative controls recover the expected exposure
  amplification;
- old-root compromise continues to expose unmigrated records but not records
  conclusively migrated to the independent new Root-Epoch;
- ambiguous remote rotation never destroys the only reconstructible credential;
- strict same-epoch duplicates remain zero over large generation runs.

## Recommended paper organization

1. Introduction and motivating compromise trace
2. Related work and novelty boundary
3. System, deployment, and adversary model
4. Exact-domain threshold functionality
5. Authorization-scoped evaluation protocol
6. Root-Epoch healing and migration state machine
7. Security properties and proofs
8. Implementation
9. Evaluation
10. Limitations and deployment guidance
11. Conclusion

## Kill criteria

Abandon or materially redesign the paper if literature review finds a published
system that already provides *all* of the following in the same legacy-password
setting:

- exact accepted-policy-space permutation;
- client-visible deterministic reconstruction;
- threshold evaluation without endpoint key reconstruction;
- exact per-generation authorization;
- root replacement after complete old-root compromise;
- failure-safe ambiguous remote password rotation; and
- cross-epoch history exclusion without a stored password vault.

Finding prior work for any individual component is expected and is not a kill
condition.
