# 证据有界凭据轮换改造记录

## 改造结论

项目和论文的主贡献已从“标准密码学组件的组合”收缩为一个可实现、可建模且具有明确不可判定边界的问题：当目标系统不参与事务、认证后端可能复制且密码更新响应可能丢失时，客户端应依据什么证据提交本地凭据代际。

核心改造是将远端状态显式建模为四元可能集合，再由带凭据类型、端点和时间的认证探测单调收缩。不同目标能力通过原子替换、先并存后撤销和不透明三种契约区分，因而“新旧凭据都有效”不再被一律误判为失败或成功。

## 论文结构对齐

- 标题、摘要、引言和贡献列表统一聚焦证据有界轮换，不宣称 Shamir、HKDF、HMAC、JCS 或密码编码器是新原语。
- 相关工作增加运维密钥轮换和双凭据能力，用于说明不同目标对 `both-valid` 的语义不同。
- 协议节给出可能集合、证据交集、三种契约、撤销后证据失效和部分端点观察的不可区分性论证。
- 实验节只报告当次原始 JSON 可核对的数据，并明确区分 Rust 状态机、TLA+ 有限模型、Redis 测试适配器与尚未完成的生产适配器验证。
- 局限与结论保留生产目标覆盖、系统故障注入、跨平台测量和恢复介质可用性四类证据缺口。

## 实现与验证

- CDR 认证保护轮换契约、端点标记探测及剩余可能集合。
- 本地提交必须已持久化的 `new-only` 单例证据；`confirm` 接口不再自行制造远端成功事件。
- 先并存后撤销在撤销操作后重置证据，防止用撤销前的观察证明撤销后状态。
- Redis 7.4 ACL 测试适配器执行真实的“新旧凭据并存→撤销旧凭据→仅新凭据”路径，CI 启动隔离 Redis 实例复现。
- TLA+ 模型生成 172 个状态、发现 79 个不同状态，最大深度 14，五个安全不变式未发现违反。

## 谨慎声明

这次改造提高了贡献的可辩识性和协议的可证明性，但不构成“已证明全球首创”或“已达到录用标准”的保证。投稿前仍需针对分布式凭据轮换、秘密管理器轮换插件、双凭据轮换、部分观察与终止检测做系统查新，并且至少再补一类异质真实目标适配器和持久化/网络边界故障注入。
