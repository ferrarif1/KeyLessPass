# 商业设备批量授权设计

English: [device-batch-authorization.md](device-batch-authorization.md)

本文说明 KeyLessPass 商业设备授权的设计边界。具体怎么部署和怎么点后台，请优先看 [device-batch-authorization-implementation.zh-CN.md](device-batch-authorization-implementation.zh-CN.md)。

## 目标

商业授权要解决的是“哪些组织、哪些设备、多少席位、多久有效、允许哪些功能”。它不属于密码派生安全边界，不能碰密码秘密。

授权系统必须做到：

- 后台能创建组织和席位；
- 每台设备有独立授权请求；
- 授权包由后台私钥签名；
- 客户端只嵌入公钥验签；
- 授权绑定当前设备；
- 复制授权包到别的电脑不能直接授权；
- 可离线批量签发；
- 可通过 HTTPS 在线激活；
- 可续期、吊销、审计和导出。

## 绝不能进入授权后台的数据

后台不能接收或保存：

- 助记短语；
- `Kmaster`；
- `deviceSecret`；
- `usbSecret`；
- CDR secret；
- 服务密码；
- 派生密码；
- recovery wrapper key。

后台只保存商业元数据，例如组织、席位、设备请求、授权包历史和审计记录。

## 授权对象

### Organization license

组织授权描述客户或组织：

- `organizationId`
- `licenseId`
- 组织名称
- 方案
- 最大席位数
- 有效期
- 功能列表
- 允许的应用主版本
- 离线宽限天数

### Device grant

设备授权书描述一台设备：

- `grantId`
- `organizationId`
- `licenseId`
- `commercialDeviceId`
- `deviceFingerprint`
- 席位标签
- 有效期
- 功能列表

客户端只有在授权包中找到同时匹配 `commercialDeviceId + deviceFingerprint` 的 grant 时才会显示已授权。

## 离线授权流程

适合隔离网、不能访问授权服务器、或管理员集中审批：

1. 客户端点击“复制设备请求”。
2. 管理员在后台导入设备请求。
3. 管理员勾选设备。
4. 管理员点击 `Issue bundle` 签发 `.klp-license-bundle`。
5. 用户在客户端点击“导入授权包”。

一个 bundle 可以包含多台设备的 grant，但每台客户端只接受自己的 grant。

## 在线激活流程

适合设备能访问授权服务的场景：

1. 管理员创建组织。
2. 管理员复制组织激活码。
3. 用户在客户端输入授权服务地址、激活码和席位标签。
4. 客户端自动生成设备请求。
5. 后台消耗一个席位并返回签名授权包。
6. 客户端验签并导入本地授权。

真实部署必须使用 HTTPS。本机测试可以用 `http://127.0.0.1:8787`。

## MDM / 托管授权包

企业可以通过 MDM 或配置管理系统把完整授权包 JSON 放到托管路径。客户端读取授权状态时会自动验签和导入。

注意：

- 授权包仍然按设备绑定；
- 多设备共用一个文件时，文件必须包含每台设备自己的 grant；
- 文件权限应允许客户端读取，但不应允许普通用户随意覆盖。

## 续期

续期时，在后台给原组织和设备签发有效期更晚的新授权包，然后分发给客户端导入或覆盖托管文件。

客户端不需要重新初始化密码数据。

## 吊销

吊销时：

1. 在后台吊销目标 grant；
2. 签发包含最新吊销列表的新 bundle；
3. 分发给客户端。

离线客户端只有收到新 bundle 后才知道新的吊销状态。

## 换电脑

新电脑会生成新的 `commercialDeviceId` 和 `deviceFingerprint`。不要复制旧电脑本地授权状态。

正确流程：

1. 在新电脑客户端复制设备请求；
2. 在后台导入；
3. 签发新 grant；
4. 在新电脑导入授权包或在线激活。

## 常见问题

### 已导入授权包但仍未授权

检查授权包里是否包含当前设备的 grant。复制授权包到未登记设备不会授权。

### 在线激活失败

检查：

- 地址是否为 HTTPS；
- 本机测试是否使用 `http://127.0.0.1` 或 `http://localhost`；
- macOS app 是否带 `com.apple.security.network.client` entitlement；
- 激活码是否属于目标组织；
- 后台是否还有剩余席位。

### 授权包可以公开吗

不建议公开。授权包不包含密码秘密，但包含组织、设备和授权标识，应按商业授权材料保存和分发。

### 授权能防破解吗

不能承诺本地二进制不可破解。授权设计用于正规商业分发、席位控制、审计、续期、吊销和支持准入。反篡改、签名安装包、更新通道和合同执行需要一起使用。
